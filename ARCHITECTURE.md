# Архитектура

HTTP management → транзакция под mutex → атомарный JSON snapshot → bounded delivery workers → HTTP receiver. Подписки и сообщения сохраняются отдельно; URL и ключ подписания заморожены на момент приёма. Перед отправкой worker сохраняет inflight и увеличивает attempts, после ответа сохраняет delivered/pending/dead. Рестарт переводит inflight в pending: возможный повтор принимается получателем идемпотентно. SIGINT/SIGTERM останавливает приём и workers; отменённая отправка возвращается в retry. Количество активных HTTP-доставок ограничено --workers.

Выбор JSON вместо embedded DB упрощает аудит и восстановление, но стоимость записи O(история). Это локальный однопроцессный инструмент, не кластерная брокерная система. Все внешние интеграции — реальные URL, заданные оператором.
